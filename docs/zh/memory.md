# 记忆检测：模型是不是记得后来发生了什么？

[English](../memory.md)

防偷看检查能证明没有任何未来的价格或标题进到 prompt 里，但看不到模型自己带进来的东西。2020 和 2022 年在所有现有模型的训练数据里，2026 年也在最新模型的训练数据里，所以问模型 2022 年 5 月 10 日的苹果，它可能直接记得苹果之后几周怎么走的。这时它在这段时间上的回测量的是记忆，不是本事。记忆检测只看模型的回答，从外面把这份记忆量出来，好让榜单标出谁在哪个时段上的成绩是干净的。

## 快速上手

```bash
riskaware research memory --llm ollama:llama3.2:3b --period 2022 --pairs 100 --cutoff 2023-12 --estimate
riskaware research memory --llm ollama:llama3.2:3b --period 2022 --pairs 100 --cutoff 2023-12
```

第一行只打印计划：要调用几次、多少 token、花多少钱。第二行真正跑，最后打印报告。`--cutoff` 是模型的训练截止日；给了它，检测还会问截止日之后的样本作对照（这里从 2026 年抽），结论才靠得住。

在 Python 里用，比如给榜单上每个模型算记忆分：

```python
from riskaware.research.memory import memory_probe

r = memory_probe("ollama:llama3.2:3b", period="2022", pairs=100, cutoff="2023-12")
r.verdict                       # "clean"、"contaminated" 或 "inconclusive"
r.memory_score                  # 截止日之前样本的 AUC 差（实名减盲测）
r.summary["memory_ci95"]        # 它的 95% bootstrap 置信区间
r.summary["recall_score"]       # 直接回忆：记得的涨跌和实际涨跌的秩相关
print(r.report("zh"))           # 中文报告（r.report() 是英文）
```

`llm` 可以是包里能调用的任何模型（`openai:gpt-5.6-luna`、`anthropic:claude-opus-5-5`、带 `base_url` 的 `compat:<模型>`、`claude-cli`、`codex-cli`、`gemini-cli`、`ollama:<模型>`），也可以是任何带 `complete_json(system, user, schema)` 的对象，或者一个普通函数（见[下文](#经批处理器或自己的调用函数)）。`period` 可以是一个自带时段，也可以是几个（`"2022,2026"`）；`pairs` 和 `recall` 都按每个时段算。

## 怎么做的

**配对探针。** 从一个时段的测试区间里随机抽（股票，日期）（同一个种子在任何机器上抽到的都一样；同一只股票的两个样本至少相隔 20 个交易日，结果窗口不重叠），每个样本给模型看两遍，两遍的信息完全相同：

- 过去 60 个交易日的收盘价，从旧到新；
- RSI(14)、距 EMA50 和 EMA200 的距离、ATR 占价格的比例、距 52 周高点的距离、相对成交量，以及 21 日收益和同期 SPY 的对比；
- 当天收盘前发布的最多三条标题，标明在收盘前几小时出现。

**实名**版本给出代码、公司名、行业、日期和真实成交价。**盲测**版本给化名（S01）、行业和「第 0 天」，价格以第一个收盘价为 100 换算，标题也做遮蔽：公司名和代码（沿用盲测交易模式的遮蔽）、最有名的人（「the S01 chief」）和产品（「[product]」），以及所有日期和年份。标题里的每股美元金额按价格同样的比例换算，所以「Raises Price Target to $264」保留了目标价和股价的距离，却不再暴露是哪只股票：

```
[a1] LLY (Eli Lilly, Health Care), close of 2022-04-13
closes (oldest first): 245.1 243.1 243.1 240.4 239.5 ... 308.4 311.7 309.0 308.1 302.7
RSI14 66 | vs EMA50 +9.2% | vs EMA200 +21.3% | ATR 2.2% of the price | from the 52-week high -3.6% | ...
headlines:
- 33h before the close: "Goldman Sachs Maintains Neutral on Eli Lilly, Raises Price Target to $264"

[a1] S01 (Health Care), close of day 0
closes (oldest first, the first = 100): 100.0 99.2 99.2 98.1 97.7 ... 125.9 127.2 126.1 125.7 123.5
RSI14 66 | vs EMA50 +9.2% | vs EMA200 +21.3% | ATR 2.2% of the price | from the 52-week high -3.6% | ...
headlines:
- 33h before the close: "Goldman Sachs Maintains Neutral on S01, Raises Price Target to $107.7"
```

两遍都问同一个问题：接下来 20 个交易日，这只股票的总收益跑赢 SPY 的概率。两个回答都用实际结果打分：准确率、Brier 分数、对数损失和 AUC。两个版本只差「是谁、是哪天」，所以一个模型知道名字和日期时答得更好，就是在用它记住的东西。实名和盲测的记录从不放在同一次调用里：放在一个 prompt 里，模型可能把盲测记录和它的实名双胞胎对上。两种版本用同一个 system prompt，里面把两种形式都说明了。

**直接回忆。** 便宜的第二个探针什么数据都不给：「AAPL (Apple)：2022-05-10 到 2022-06-08，算上分红、按拆股调整，涨了还是跌了，大约多少个百分点？」不记得的模型只能猜，猜出来的涨跌幅排不出实际涨跌的顺序。打分看两样：方向猜对的比例，和「一直猜更常见的方向」比；猜的和实际的涨跌幅的秩相关，两者都先除以这只股票平常 20 天的波动幅度（用窗口之前的波动率算）。不除的话，一个只知道 2022 年整体下跌、又知道哪些股票波动大的模型，不记得任何一只股票也能排对顺序；没除的秩相关也一并报告。每个时段前 `recall` 个样本这样问一遍。

## 记忆分

记忆分是 **AUC 差**：实名回答的 AUC 减盲测回答的 AUC。AUC 是「一只跑赢 SPY 的股票拿到的概率高于一只没跑赢的」的机会，所以这个差说的是：知道名字和日期后，模型把赢家和输家分开的能力好了多少。它带一个配对 bootstrap 置信区间（重抽 2,000 次；同一周决策的样本共享市场的涨跌，所以按周整组重抽）和一个置换检验 p 值：把每个版本的回答换成名次，再随机交换一些样本的两个名次；名字不带任何信息时，交换不会有影响。

为什么用 AUC 而不是 Brier：格式可能让模型的回答整体挪动。第一次测试调用里，Llama 3.2 3B 给 5 条盲测记录的概率都在 0 到 0.012 之间。Brier 分数、对数损失和准确率会把这种整体挪动算成预测变好或变坏，其实和记忆无关；AUC 只看回答把股票排成什么顺序，一个版本整体挪动不影响它。准确率、Brier 和对数损失的差照样报告，各带置信区间。

## 训练截止日和对照

给了模型的训练截止日（`--cutoff 2025-06` 指整个 2025 年 6 月），每个样本落进三个窗口之一：

- **之前**：整个结果窗口在截止日之前结束，模型可能读到过结局；
- **之后**：决策日在截止日之后，模型不可能读到；
- **跨过**：两边都不是，不计入。

截止日之后的样本就是**对照**。格式在那里照样可能帮忙或添乱（模型可能就是读真实价格比读换算后的价格更顺），但记忆帮不上忙。所以检测把截止日之前的差和之后的差相比，并给出这个差值的置信区间。请求的时段里截止日之后不到 30 个样本时，会自动加上截止日之后还有足够交易日的最新自带时段（截止日不晚于 2026 年 8 月中旬的都会加 2026），从截止日之后的交易日里抽 `pairs` 个样本；`--no-control` 可以关掉。

## 结论

| 结论 | 含义 |
|---|---|
| `contaminated`（有记忆） | 有对照时：截止日之前的差比之后的大（差值的 95% 置信区间在 0 以上）。没有对照时：差的置信区间在 0 以上。 |
| `clean`（干净） | 截止日之前的差的置信区间上端低于 0.05 AUC，或者它和截止日之后的差相差不到 0.05。样本全在截止日之后的，按定义就是干净的。 |
| `inconclusive`（无法判断） | 成对样本不到 30 个；模型给每条实名记录同一个概率；置信区间太宽；截止日之后的差差不多一样大（是格式的影响，或者截止日比给的晚）；或者预测看起来干净，但直接回忆显示模型记得涨跌。 |

0.05 是有意义的最小 AUC 差：挑一个月内跑赢 SPY 的股票，AUC 0.55 对 0.50 就是实实在在的优势。要把这么小的差和 0 分开，需要几百对样本；如果模型两个版本的回答很接近，配对设计需要的少得多。

不给 `--cutoff` 时，结论只看差本身，报告会说明格式的影响和记忆分不开。

## 花费和缓存

- **打包。** 默认每次调用放 5 条记录（`--batch`），直接回忆每次 10 条。一条带标题的记录约 400 token，一次调用约 2,300 token。Ollama 的调用会控制在 3,200 token 以内：它默认的上下文是 4,096 token（0.11 版），更长的 prompt 会被悄悄从前面截掉。
- **缓存。** 每个回答都存在 `~/.riskaware/research/memory/cache/<模型>.jsonl`，按模型、记录和所有会改变 prompt 的设置（包括每次打包的条数）区分。重跑不花钱；以后跑更大的样本，会先用到小样本里已经问过的那些，只为新样本付钱。
- **估价。** `--estimate` 打印调用次数和 token 数，给了价格（`--price-in` 和 `--price-out`，每百万 token 的美元价）时也打印花费。Ollama 模型和 `-cli` 订阅算免费。估价超过 `--max-cost`（默认 5 美元）时，第一次调用前就停下；付费模型没给价格，只有加 `--yes` 才跑。Python 里 `max_cost` 作用相同，`plan_probe(...)` 只返回计划、不调用模型。
- **规模。** 100 对加 50 个回忆窗口，每个时段 45 次调用、约 95,000 输入 token；加上对照时段翻一倍。

## 经批处理器或自己的调用函数

调用不一定要由检测自己发。用请求队列或批处理 API：

```bash
riskaware research memory --llm gpt-5.4-nano --period 2022,2026 --cutoff 2025-08-31 --export-requests requests.jsonl
# 在队列或批处理 API 上跑完 requests.jsonl，再用同样的参数打分：
riskaware research memory --llm gpt-5.4-nano --period 2022,2026 --cutoff 2025-08-31 --import-results results.jsonl
```

每条请求是一行 JSON：`key`、`prompt`、`system`（末尾带回复的 JSON schema，和直接调用时一样）、`temperature`、`max_tokens` 和 `meta`；`meta` 写着这条请求里每条记录的缓存键。结果文件每行要带回 `text` 和 `meta`；有 token 数的话会累加。回答存进缓存，打分时不调用任何模型。Python 里是 `export_requests(plan_probe(...), path)`、`import_results(path)`，再 `memory_probe(..., offline=True)`。

一个函数也可以当模型用，比如每次调用都记账的函数：`memory_probe(fn, period="2022", cutoff="2025-08-31", model_id="gpt-5.4-nano")`，`fn(system, user)` 返回回复的文本（或 dict）。它必须给 `model_id`，回答按这个名字缓存。`temperature=` 要填这个函数实际用的温度：只有检测自己调用的模型，温度才由检测来设，而缓存键无论哪种情况都会记下温度。

## 一次运行留下什么

`~/.riskaware/research/memory/runs/` 下（或 `--out` 指定）的一个文件夹：

| 文件 | 内容 |
|---|---|
| `memory.json` | 结论和理由；`memory_score` 及其 `memory_ci95`、`memory_p_value`；`memory_beyond_control` 及其置信区间；`recall_score` 及其 `recall_ci95`、`recall_verdict`；两个版本的全部分数，分总体、分时段、分窗口；直接回忆的分数；估价和实际用量；数据的 SHA-256；设置和 system prompt |
| `answers.csv` | 每个样本一行：股票、日期、结果、两个概率、回忆的回答、所在窗口 |
| `report.md`、`report_zh.md` | 英文和中文报告 |
| `example_prompts.json` | 第一条实名、盲测和回忆 prompt，和发出去的一字不差 |

## 第一次实跑：gpt-5.6-luna 和 gpt-5.4-nano

两个 OpenAI 模型，各跑 2022 和 2026，用默认设置：每个时段 100 对加 50 个回忆窗口，种子 0，每次调用 5 条记录，温度 0。调用经请求队列发出（先 `--export-requests`，再 `--import-results`）：每个模型 90 次调用、185,250 输入 token，按标价约 5 美分。训练截止日取自 OpenAI 的模型页：gpt-5.6-luna 是 2026 年 2 月 16 日，gpt-5.4-nano 是 2025 年 8 月 31 日，所以 2022 年在两个截止日之前，2026 年大部分在之后。

| | gpt-5.6-luna | gpt-5.4-nano |
|---|---|---|
| 截止日之前的样本 | 109 对（2022 年和 2026 年开头几天） | 100 对（2022 年） |
| 截止日之前预测的 AUC，实名 / 盲测 | 0.490 / 0.537 | 0.651 / 0.592 |
| **记忆分**（AUC 差），截止日之前 | −0.047 [−0.180, +0.093] | +0.059 [−0.004, +0.138]，p = 0.04 |
| 同样的差，截止日之后（对照） | −0.009 [−0.174, +0.148]，83 对 | +0.007 [−0.082, +0.101]，100 对 |
| 之前减之后 | −0.038 [−0.236, +0.189] | +0.052 [−0.064, +0.168] |
| 截止日之前的 Brier 差 | −0.0025 [−0.0199, +0.0156] | +0.0145 [+0.0025, +0.0287] |
| 截止日之前的回忆：方向答对（最好的固定猜法） | 75%（53%） | 42%（54%） |
| **截止日之前的回忆**：秩相关 | +0.69 [+0.51, +0.80] | −0.03 [−0.35, +0.28] |
| 截止日之后的回忆：秩相关 | +0.25 [−0.05, +0.55] | +0.21 [−0.09, +0.47] |
| 结论 | 无法判断 | 无法判断 |

**gpt-5.6-luna 记得 2022 年。** 不给任何数据问它，它说对一只股票 20 天涨跌方向的次数是四次里有三次，一直猜更常见的方向只有 53%；它猜的涨跌幅也排得出实际涨跌的顺序（两者都除以这只股票平常的波动幅度后，秩相关 0.69）。截止日之后同一个相关只有 0.25，置信区间包含 0。可它的预测并没有用上这份记忆：实名记录把赢家排在前面的本事，并不比盲测记录强。结论是「无法判断」，报告也写明了理由：记忆在，这个任务看不出它在起作用，换一种问法的策略可能就用上了。

**gpt-5.4-nano** 被直接问时不记得 2022 年，但它对 2022 年实名记录的预测比盲测稍好：AUC 差 +0.059（置换检验 p = 0.04），Brier 差的置信区间也在 0 以上。截止日之后这个差是 +0.007。两个窗口之差 +0.052 [−0.064, +0.168]，每个窗口 100 对时还分不清是记忆还是偶然，大约要 500 对。

直接回忆最能看出模型知道什么；配对差才是回测关心的；一个模型可能只露出其中一样。两个模型在 2022 年盲测的 AUC 都高于 0.5（0.537 和 0.592），可能是本事，也可能是时段通过行业和标题透了出来（见局限）。

## 局限

- **盲测记录里仍有线索。** 合作方、药名、CEO 以外的高管、罕见事件都可能暴露是哪只股票；模型从标题、SPY 的 21 日涨跌或价格走势认出了是哪段时间，也还能用它对那段时间的了解。这会让盲测版本也用上一部分记忆，所以差只会低估记忆，不会高估。
- **格式的影响。** 真实价格和换算后的价格读起来不一样。把这一点和记忆分开靠的是对照窗口；没有截止日时，有差只是警告，不是证明。
- **统计功效。** 几十个样本上的 AUC 噪声很大。每个窗口 100 对能把很强的记忆和没有记忆分开；要证明「干净」到 0.05 以内需要几百对，或者模型两个版本的回答本来就很接近。
- **一个问题，一种 prompt。** 检测量的是温度 0 时、在这个 prompt 下、体现在 20 日预测里的记忆。模型交易时用记忆的方式可能不同，所以也问了直接回忆。
- **价格按后来的拆股调整过**，和自带数据、交易观察里一样，所以实名价格可能和当时报的价格不一样。

## 相关工作

- Haozhe Jia，"HindsightBench: A Black-Box Behavioral Audit Protocol for Parametric Hindsight in Time-Indexed LLM Decision Tasks"，[arXiv:2607.18867](https://arxiv.org/abs/2607.18867)，2026。把按时间编号的任务做成带日期和不带日期、内容遮蔽和替换的几个版本对比，再加上恢复日期和回忆结果两个探针；在 15 个模型上发现实际起作用的截止日常常早于厂商公布的。这里的检测把同样的配对思路用到单只股票上，并用实际结果给回答打分。
- Joohyoung Jeon、Hongchul Lee，"Can Blindfolded LLMs Still Trade? An Anonymization-First Framework for Portfolio Optimization"，[arXiv:2603.17692](https://arxiv.org/abs/2603.17692)，2026。对 LLM 交易智能体隐藏代码和公司名，让它们的信号不能来自记住的代码。
- Mostapha Benhenda，"Look-Ahead-Bench: a Standardized Benchmark of Look-ahead Bias in Point-in-Time LLMs for Finance"，[arXiv:2601.13770](https://arxiv.org/abs/2601.13770)，2026。通过真实金融工作流程中表现跨市场阶段的衰减来量偷看偏差。
