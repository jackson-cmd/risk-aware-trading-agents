# LLM 交易智能体榜单（rta-bench-1）

[English](../leaderboard.md) · [网站上的榜单](https://jackson-cmd.github.io/risk-aware-trading-agents/zh/leaderboard.html)

rta-bench-1 是在[研究工具箱](research.md)的冻结市场上给 LLM 交易智能体定的一套固定玩法。每个模型交易同样的 56 只美股大盘股，走完 2026 年至今、2022 年熊市和 2020 年暴跌三个时段，每隔 5 个交易日收盘后决策一次，看到的价格、指标和新闻都按发布的那一分钟回放。每个时段跑两次，一次用真实名字，一次盲测。模型的训练截止日决定哪些成绩算本事：截止日之后的参与排名，之前的单独列出。一个条目就是一个 JSON 文件，里面存着模型的全部回复，任何人都能重放它、得到同样的数字，不用再调用模型。

## 任务

| 任务 | 窗口 | 决策次数 | 模型面对的行情 |
|---|---|---|---|
| `2026-blind`、`2026-named` | 2026-01-02 到 2026-11-11 | 44 | 上涨行情，春季有一波下跌 |
| `2022-blind`、`2022-named` | 2022-01-03 到 2022-12-30 | 50 | 加息熊市 |
| `2020-blind`、`2020-named` | 2020-01-02 到 2020-12-31 | 51 | 疫情暴跌和反弹 |

盲测任务里，股票代码换成 S01、S02 这样的代号，日期换成第几天，价格从第一天的 100 起算，新闻标题里的公司名和代码也换成同样的代号。实名任务什么都不藏。

所有任务用同一套设置（`riskaware.research.bench.SETTINGS`）：

| 设置 | 取值 |
|---|---|
| 股票 | `megacap` 列表的 56 只，分属 11 个行业 |
| 决策 | 每 5 个交易日收盘后一次（`decide_every=5`），订单在下一个交易日开盘成交 |
| 仓位 | 只做多，最多 10 个，初始 10 万美元，没投出去的现金按短期国债 ETF BIL 计息 |
| 新闻 | 开；每次决策每只股票最多 3 条当天收盘前已发布的标题 |
| 执行 | 朴素执行：只照模型的订单做，上面不加风控规则 |
| 成交成本 | realistic：5 bp，加隔夜跳空的十分之一，加平方根冲击成本，单笔成交不超过平均成交量的一定比例（[成本说明](costs.md)） |
| 种子 | 0、1、2，每个种子一个条目：种子决定盲测的代号分配，接口支持时也用作采样种子。榜单显示一个模型各个种子的平均和范围；种子少一些也接受，会照实显示 |

榜单自己跑的模型用的是包里的系统提示词（`research.agent.SYSTEM_PROMPT` 加订单格式），温度 0.2，输出最多 2,000 token，接口有开关的一律关掉推理。提交的模型可以用别的调用方式，条目里写明就行。

## 为什么这样定

**用 56 只而不用更小的列表。**模型能在行业之间做选择，才看得出它靠什么赚钱。在这 56 只里，2022 年能源股平均涨了 73%，科技股跌了 32%；2020 年能源跌了 31%，科技涨了 58%；2026 年能源（+43%）和医疗（+25%）跑赢了科技（+12%）。`tech` 列表的 18 只只给模型留下一个行业加现金。代价是 token：用每个模型自己的分词器在真实观察值上量，榜单自己跑的这几次里，megacap 上一次决策的平均输入，GPT-5.6 Luna 是 10,900 到 11,900 token，Claude Sonnet 4.6 是 12,300 到 13,500，Gemini 3.5 Flash 是 13,700 到 14,700（`core` 的 9 只股票上 Luna 是 2,800；`tech` 约为 megacap 的四成）。六个任务共约 290 次决策，每个种子 300 万到 450 万输入 token：按标价，小模型远不到 1 美元，Sonnet 级别的模型约 10 到 15 美元（三个种子再乘三）。[研究文档](research.md#五种波段策略开和不开新闻)里的五个规则策略也跑在这 56 只上，正好当锚。

**每 5 个交易日一次。**日线波段交易一拿就是几天到几周；每周决策一次保留这个节奏，token 只有每天决策的五分之一。

**盲测和实名都跑。**盲测降低模型想起某只股票表现的可能；实名看它把知道的一切都用上会怎样。两者之差本身就是一个现成的记忆检查。

## 干净的和可能记得的成绩

每个条目都写明模型的训练截止日（`--cutoff YYYY-MM`，取厂商模型页上的训练数据截止日，不是发布日期）。对每个时段：

- `clean`（干净）：窗口在截止日之后才开始，模型不可能读到过。
- `partly`（部分干净）：截止日落在窗口里。条目会另外从截止日当天或之前最后一个收盘开始计分（`after_cutoff`），并给出同一段日子里 SPY 和等权组合的表现。
- `may_remember`（可能记得）：窗口在截止日之前就结束了。单独列出，不算本事：就算盲测，模型也可能记得发生过什么，因为盲测保留了每只股票所属的行业。

网站上干净的那张表用的是 `after_cutoff` 的成绩，所以表里每个模型都只在它不可能知道的日子上计分。

## 跑一个模型

```bash
riskaware research bench --llm openai:gpt-5.6-luna                   # 全部六个任务，种子 0、1、2
riskaware research bench --llm ollama:llama3.2:3b --task 2026-blind --seed 0   # 一个任务、一个种子，本地模型
riskaware research bench --llm compat:deepseek-chat --base-url https://api.deepseek.com/v1
riskaware research bench --llm claude-cli                             # 用你的 Claude 订阅
```

跑模型需要榜单用的那几个新闻文件：2020、2022 和 2026 年的标题有许可限制，不随包分发，请把你的副本放进 `~/.riskaware/data/news`（或 `RISKAWARE_NEWS_DIR` 指定的文件夹）。没有的话 `riskaware research bench` 会在调用模型之前停下。用你自己的新闻文件跑，就是换了一份数据：照样能跑，但 SHA-256 和 manifest 对不上，`submit` 不会收。

每次运行跑完会打印结果、用了多少 token，以及提交用的命令。本地模型走 Ollama 的原生聊天接口，上下文开到 16,384 token：Ollama 的 OpenAI 兼容接口沿用服务端默认上下文（Ollama 0.11 是 4,096 token），更长的 prompt 开头会被悄悄截掉，而 megacap 的一个观察值约 1 万 token。

在 Python 里，任何「观察值 → 订单」的函数都是一个策略：

```python
from riskaware.research import bench

policy = bench.bench_policy("openai:gpt-5.6-luna")      # 或者你自己的函数：observation -> {"orders": [...]}
result = bench.run_task(policy, "2026-blind", label="my-model")
print(result.summary()["metrics"], result.folder, policy.usage)
```

## 提交条目

```bash
riskaware research submit RUN_ID --model gpt-5.6-luna --cutoff 2026-02 --provider OpenAI --closed-weights
```

`submit` 先按基准核对这次运行，再写出 `leaderboard/entries/<model>-<task>-s<seed>.json`。设置不同、数据不同或防偷看检查没过的运行会被拒绝，并列出每一处不同。在 realistic 成交成本出现之前跑的运行，会先在这个成本下重放一遍：模型的订单不变，成交按基准的成本算。可选参数：`--access`（怎么调用的模型）、`--parameters`（模型大小）、`--submitter`、`--notes`、`--memory`（模型记忆探针结果的 JSON 文件）。

然后开一个只加这个文件的 PR。CI 会重放每个条目并重新生成网站上的表格；维护者合并后，下一次部署时榜单就更新了。在仓库目录里运行 `riskaware research leaderboard` 可以在终端里看榜单，加 `--verify` 自己重放每个条目（不需要新闻文件：回复是固定的）。

## 条目里有什么

| 字段 | 内容 |
|---|---|
| `bench`、`task`、`seed` | `rta-bench-1`、任务名和种子 |
| `model` | 名字、厂商、怎么调用的（`access`，`call`：温度、token 上限、推理设置）、`training_cutoff`、`open_weights`、`parameters` |
| `contamination` | `clean`、`partly` 或 `may_remember`，由截止日和窗口推出 |
| `settings`、`data` | 实际运行时的基准设置，以及价格和新闻文件的 SHA-256 |
| `record` | 运行编号、包的版本和提交、记录里每个文件（manifest、metrics、equity、trades、decisions、policy log）的 SHA-256、公开的回复和观察值的 SHA-256；模型当时看到的持仓用的是哪种成交成本；如果是重放出来的，原来的运行编号 |
| `look_ahead_check` | 观察值防偷看检查的结论（必须是 `pass`） |
| `metrics`、`vs_spy`、`anchors` | 收益、Sharpe、Sortino、回撤、换手、持仓比例、持有天数、交易次数；beta、alpha、信息比率、t 统计量和 Sharpe 的 bootstrap 区间；同一窗口里 SPY 和等权组合的表现 |
| `after_cutoff` | 同样的指标，只算截止日之后的日子，`clean` 和 `partly` 窗口才有 |
| `analysis` | 这次运行的[运行分析](analysis.md)：摘要（暴露和 alpha、决策后相对 SPY 的超额、命中率、IC、新闻触发的比例）、结论、决策和 IC 的统计、因子回归，以及按持有期、行业、市场状态、触发原因和个股拆开的盈亏（各取前三和后三） |
| `memory` | 记忆探针的结果（如果提供了） |
| `usage` | 调用次数、输入输出 token、无法使用的回复、耗时、按标价的花费 |
| `replies` | 模型的全部回复，按顺序，只保留订单（代码、动作、权重、比例）：每笔订单的理由和每次回复的说明都去掉了，因为它们可能复述模型读到的、有许可限制的新闻标题 |

## 怎么核对条目

两层，都不调用模型：

1. **格式**（`bench.check_entry`，每次跑测试都会做）：设置是基准的设置，价格哈希是自带文件的哈希、新闻哈希是该时段 manifest 里记的那个，回复里只有订单并且和它的哈希对得上，防偷看检查通过，`contamination` 标签和截止日一致。
2. **重放**（`bench.verify_entry`、`riskaware research leaderboard --verify`，以及每个改动 `leaderboard/` 的 PR 都会跑的 leaderboard 工作流）：把回复一步一步重新放进回测，收益、Sharpe、回撤、平仓次数和换手必须一致。

一次运行的防偷看检查，会把它的回复放到另外几份市场副本上重放：这些副本在三个切点之后的价格和新闻全是随机的。每个切点之前的观察值必须完全相同，这就证明了没有任何未来的信息进入 prompt。模型是否记得这个时段是另一个问题，要靠截止日划分、实名减盲测的差距和记忆探针来回答。

## 每个模型靠什么赚钱

网站上的两张表来自每次盲测记录的[运行分析](analysis.md)（`research.analysis.analyze_run`），存在条目里：

- **收益从哪来。**把运行相对短期国债的日收益，对四个用自带价格算出的因子做回归：大盘（SPY 减 BIL）、规模（IWM 减 SPY）、成长（QQQ 减 SPY）和动量。因子暴露能解释的部分折成年化，剩下的是 alpha，附 Newey-West t 值。KTD-Fin（arXiv 2605.28359）发现 LLM 交易员赚的钱大多来自大盘和风格暴露，这里就是在检查这一点。旁边还有：平均股票仓位、市场 beta、赚得最多和亏得最多的行业（每个头寸的盈亏，按占初始 10 万美元的比例），以及平均持有天数。
- **决策好不好。**每一笔买入和卖出，从成交起 5 个交易日里这只股票相对 SPY 的收益（买入记它多赚的，卖出记它躲开的），t 值考虑了同一天的多笔决策和重叠的窗口；做对的比例；模型的操作和之后 5 天收益的秩相关（IC）；理由里引用新闻的决策占多少，以及因新闻建仓的头寸赚了多少。

## 榜单自己跑的模型

榜单上线时有六个模型，全部用上面的系统提示词和设置调用（温度 0.2，输出最多 2,000 token，接口有开关的一律关掉推理或思考）。

| 模型 | 厂商 | 调用方式 | 训练截止日 | 截止日的来源 |
|---|---|---|---|---|
| `llama3.2` | Meta | 一个 OpenAI 兼容网关，后面是 Ollama 的 `llama3.2`（3B），每个请求带 `num_ctx` 16384 | 2023-12 | Llama 3.2 模型卡："The pretraining data has a cutoff of December 2023" |
| `gpt-5.6-luna` | OpenAI | OpenAI API，`reasoning_effort` none，JSON 模式 | 2026-02-16 | OpenAI 模型页："Feb 16, 2026 knowledge cutoff" |
| `claude-haiku-4.5` | Anthropic | 一个 OpenAI 兼容网关，关闭思考 | 2025-07 | Anthropic 模型页：训练数据截止 2025 年 7 月（可靠知识截止 2025 年 2 月） |
| `claude-haiku-5.5` | Anthropic | Anthropic API，关闭思考；只有种子 0 的三个盲测任务 | 2026-06 | Anthropic 模型页：训练数据截止 2026 年 6 月 |
| `claude-sonnet-4.6` | Anthropic | 一个 OpenAI 兼容网关，关闭扩展思考 | 2026-01 | Anthropic 模型页：训练数据截止 2026 年 1 月（可靠知识截止 2025 年 8 月） |
| `gemini-3.5-flash` | Google | 一个 OpenAI 兼容网关，`reasoning_effort` minimal | 2025-01 | Box 模型列表里 Gemini 3.5 Flash 的模型卡：知识截止 2025 年 1 月；Google 自己的模型卡指向 Gemini 3 Flash，没写日期 |

所以 2026 年对 Llama、Haiku 4.5 和 Gemini 是干净的，对 Sonnet 4.6（从 1 月 30 日起计分）、Luna（从 2 月 13 日起）和 Haiku 5.5（从 6 月 30 日起）是部分干净的，2022 和 2020 年六个模型都可能记得。Luna 六个任务三个种子都齐了。Llama、Haiku 4.5 和 Gemini 六个任务都有种子 0；Llama 和 Gemini 的种子 1、2 随运行完成补上，Haiku 4.5 只有一个种子，因为请求队列限制了一个项目调用 Claude 的次数。Sonnet 4.6 有六个任务里的四个、一个种子，Haiku 5.5 只有一个种子的三个盲测任务。榜单在每个模型名下写明它的运行日期。

最早一批盲测（2026 年 11 月 13 日，在包里把新闻标题中的日期和美元金额也遮住之前）在部分标题里仍能读到日期或目标价，之后的运行读不到。每个条目都记着运行时包的版本和提交。

跑的时候踩到两个坑。Ollama 除非请求里要求，否则上下文只有 2,048 或 4,096 token，更长的 prompt 会被从开头截掉，而且不报错：通过网关，`llama3.2` 对一个 9,400 token 的观察值只报了 2,050 个 prompt token，回复也只是照抄一条股票记录；设了 `num_ctx` 之后就全读进去了。`bench_policy("ollama:...")` 对本地服务会设好它。另外，OpenAI 兼容网关在请求里不写 `"stream": false` 时可能按流式返回，现在包里的 provider 会写上。

## 局限

- **每个任务跑三个种子。**同一个模型跑两次，采样会让结果不同。榜单显示各个种子的平均和范围；比范围小的差别当成噪声。
- **幸存者偏差。**这 56 只是今天的大盘股。2020 年把它们全部买入持有能赚 40%，远超当时任何人的预期；模型之间、模型和规则策略之间比，不要只和等权组合比。
- **盲测不是密不透风。**盲测藏起了代码和公司名，但新闻标题里仍可能带着日期（比如标题里写着星期几和日期的每日汇总），或者带着能看出价位的美元目标价；行业、价格走势和一条特别的新闻合在一起，也可能让模型认出某只股票。
- **每个时段只有十到十二个月。**样本短；每个条目里 Sharpe 的区间说明了有多短。
- **新闻只有一个来源。**一个有许可的标题来源，2026 年另有 SEC 8-K 公告。
